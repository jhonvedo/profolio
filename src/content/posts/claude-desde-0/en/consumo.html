Every message you send makes Claude Code send the model the whole accumulated context. That's why usage depends less on how much you write and more on how much context you drag along. The goal isn't to spend as little as possible at any cost, but to stop paying for tokens that add nothing: a small, relevant context is cheaper and gets better answers.

What loads and how much space it takes

Not everything enters in full on every turn. Many pieces put only one line in the context and load the rest when needed:

How to measure it

  • /contextWhat's taking up the context right now and how much is left: memory, MCP, skills, history.
  • /usageThe session's tokens and cost. On Pro, Max, Team and Enterprise it also shows how much of your recent usage came from each skill, subagent, plugin and MCP server, and flags anything (long context, cache misses) above 10%.
  • Status lineThe context % always in view (session 4).
  • count_tokensAPI endpoint that counts a text before you send it.
Measure before optimizing. A week of watching /usage tells you more than any general rule: it shows whether the weight comes from an MCP server, a skill, subagents, or sessions that never get cleared.

Worth knowing

  • Cache: what repeats every turn is reused from cache and costs less, but it still takes up space. It lasts an hour on a subscription and, by default, five minutes with an API key: after a long break, the first message reprocesses the whole context.
  • Output: it costs more than input, and reasoning counts as output.
  • Auto-compaction: when the context nears its limit, Claude Code summarizes it on its own and details get lost. Better to decide when yourself.
  • /compact isn't free: it reads the whole conversation to summarize it. /clear costs nothing.
  • Subagents save context, not usage: their requests also count against your plan. That's why it pays to give them a smaller model.

Make Claude read less

Don't do thisDo this
«Read logs/app.log and tell me why the payment fails» (10,000 lines).Filter first: «Run grep -n ERROR logs/app.log | tail -50 and explain what's failing». From tens of thousands of tokens to hundreds.
Run the whole suite and let the full output into the context.Ask for just the affected tests («run dotnet test --filter RefundServiceTests») or use a hook that only lets failures through (example below).
Let Claude look for a method with grep and open file after file until it finds the right one.Install the code intelligence plugin for your language (explained below). Claude asks the language where something is defined and used, just like your IDE with F12, and gets the exact path and line in a single query.
Ask it to investigate how something works inside your main session.«Use the Explore subagent to find out how a refund is calculated; return only paths and one line per file.» What it reads stays in the subagent (see Skills and subagents).
.claude/hooks/failures-only.sh · PreToolUse with matcher "Bash"
#!/usr/bin/env bash
# If the command runs tests, let only the failures through to Claude.
# Adapted from the example in the official cost documentation.
INPUT=$(cat)
CMD=$(echo "$INPUT" | jq -r '.tool_input.command')
if [[ "$CMD" =~ ^(dotnet\ test|pnpm\ (-r\ |--filter\ [^\ ]+\ )?test) ]]; then
  FILTERED="$CMD 2>&1 | grep -i -A 5 -E '(fail|error)' | head -100; echo '(filtered output: failures only)'"
  echo "$INPUT" | jq --arg c "$FILTERED" \
    '{hookSpecificOutput: {hookEventName: "PreToolUse", permissionDecision: "allow", updatedInput: (.tool_input + {command: $c})}}'
else
  echo "{}"
fi

The hook rewrites the command before it runs: Claude sees up to 100 lines around the failures instead of the whole output. Register it in .claude/settings.json under PreToolUse with "matcher": "Bash", like the hooks in session 5. On Windows, when Claude runs the tests with the PowerShell tool, this hook doesn't fire: it's written for bash.

What an LSP plugin is and why it saves tokens

Your IDE knows where every method is defined because it uses a language server (LSP): it's the engine behind F12, «Go to definition» and «Find references». Claude Code doesn't include one by default, so to find a method it searches text: it runs a grep, gets ten matches (comments, tests, similar names) and opens several files until it finds the right one. Every file it opens is tokens.

With the plugin, Claude asks the language server and gets the exact path and line. It also sees compile errors as soon as it edits a file, without waiting for the build.

Install the plugin for your language
# 1. Once per machine: the language server
dotnet tool install --global csharp-ls                 # .NET
npm i -g typescript-language-server typescript         # Node / TypeScript

# 2. In Claude Code: the plugin from the official marketplace
/plugin install csharp-lsp@claude-plugins-official
/plugin install typescript-lsp@claude-plugins-official

# 3. Ask as usual; Claude uses the language server when it helps
> Where is CalculateRefund defined and who calls it?

Model and effort

Don't do thisDo this
Opus or Fable on max to rename or format.Step down for that task: /model → pick Sonnet → use ← → to reach low → press s (this session only). Save the big model and xhigh for the hard stuff (see Concepts).

Rule of thumb: if Claude slows down or starts forgetting things, check /context before blaming the model. Usually there's too much history or files read for another task.
