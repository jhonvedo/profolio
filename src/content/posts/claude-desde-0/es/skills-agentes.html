Skills y subagentes son las dos piezas que más se confunden, porque las dos sirven para darle trabajo a Claude. La diferencia está en quién lo hace y con qué contexto. Este capítulo amplía la tabla de Conceptos; en la sesión 5 se crean en el repo.

Cursos complementarios: Introduction to Agent Skills · Introduction to Subagents

Skill vs. agente: la diferencia que más confunde

Skill = "cómo se hace"

Es conocimiento procedimental. Mientras no se usa, Claude solo ve su nombre y descripción (unas pocas líneas). Cuando se invoca, sus instrucciones entran al contexto de la conversación actual y el mismo Claude las sigue. Tú ves cada paso.

Ejemplos: crear una migración de EF Core, preparar un release, el formato del changelog, el checklist de un endpoint nuevo.

Subagente = "quién lo hace"

Es un trabajador aparte. Arranca con un contexto limpio (no ve tu conversación), usa solo las herramientas que le permitas y puede usar otro modelo. Puede leer 40 archivos y devolverte un resumen de 20 líneas: tu sesión principal no se llena.

Ejemplos: revisor de seguridad, investigador del código, escritor de tests, analista de logs.

Cómo se combinan

No hay que elegir entre una y otro. Se pueden usar juntos de tres formas.

1 · Una skill que se ejecuta en un subagente. Normalmente una skill corre dentro de tu conversación. Con context: fork (detalle abajo), Claude Code crea un subagente, le pasa la skill como tarea y a tu conversación solo vuelve el resumen; mientras tanto puedes seguir trabajando. agent: elige qué subagente hace el trabajo (si no lo indicas, general-purpose).

.claude/skills/investigar/SKILL.md
---
description: Investigates how something works in this repo and returns a short summary with file paths. Use it for questions that require reading many files.
context: fork
agent: Explore
---
Investiga $ARGUMENTS en este repositorio: encuentra los archivos relevantes,
léelos y devuelve un resumen corto con rutas y líneas.

¿Qué es agent: Explore? Le dice a Claude Code qué subagente ejecuta la skill. Explore viene incluido en Claude Code y está hecho para buscar: encuentra y lee archivos, pero no puede editarlos, y arranca con un contexto mínimo (no carga el CLAUDE.md). Es la opción natural para una skill que solo investiga. Las alternativas:

  • agent: ExploreSolo lectura y rápido. Para investigar, buscar o resumir.
  • agent: PlanInvestiga para armar un plan, sin editar.
  • agent: general-purposePuede leer, editar y ejecutar comandos. Es el que se usa si no pones agent:.
  • agent: revisor-seguridadCualquier subagente propio de .claude/agents/, con su prompt, herramientas y modelo.
Así se ve al usarla (ilustrativo)
> /investigar cómo se calcula un reembolso parcial

# Claude Code crea un subagente Explore y le pasa la skill con tu argumento.
# Tú sigues trabajando. El subagente, por su cuenta:
#   busca "Refund" → 14 archivos · lee el servicio, la política de descuentos y los tests
# Nada de eso entra a tu contexto. Cuando termina, llega solo esto:

El reembolso parcial se calcula en RefundService.CalculateRefund
(src/Payments/RefundService.cs:88)RefundService.calculateRefund
(apps/api/src/refunds/refund.service.ts:88). Aplica el descuento del pedido
y redondea al final. Los tests cubren descuentos fijos, pero no porcentuales.

El subagente leyó catorce archivos; tu sesión solo recibió cuatro líneas.

2 · Un subagente que arranca sabiendo una skill. Con skills: en el frontmatter del subagente, el contenido completo de esas skills entra a su contexto desde el inicio, sin que tenga que buscarlas. Cuando Claude delega en implementador-api, ese subagente ya conoce las convenciones del equipo desde el primer mensaje.

.claude/agents/implementador-api.md
---
name: implementador-api
description: Implements API endpoints following the team's conventions.
skills: [convenciones-api]
---
Implementa el endpoint que te pidan siguiendo las convenciones precargadas.

3 · Una skill que reparte el trabajo entre subagentes. Aquí la skill no lleva context: fork: corre en tu sesión porque es la que coordina. En cada paso le pide a un subagente distinto que haga una parte, y cada uno trabaja en su propio contexto y devuelve solo su resultado. La skill junta las respuestas y te entrega el resumen.

.claude/skills/revisar-rama/SKILL.md
---
description: Reviews the current branch before opening a PR (scope, tests, security). Only when the user runs /revisar-rama.
disable-model-invocation: true
---
Revisa la rama actual antes de abrir el PR:
1. Delega al subagente Explore: lista los archivos que cambiaron respecto a main
   y qué módulos tocan. Pide solo rutas y una línea por módulo.
2. Delega a escritor-tests: comprueba que cada cambio tenga test y escribe los que falten.
3. Delega a revisor-seguridad: revisa el diff y reporta hallazgos con archivo y línea.
4. Con los tres resultados, entrégame una tabla: módulo → tests → hallazgos.

Al escribir /revisar-rama, tu sesión ve tres delegaciones y tres resúmenes, no los archivos que leyó cada subagente. revisor-seguridad es el subagente de la sesión 5; escritor-tests sería otro igual, con permiso para editar archivos de tests.

disable-model-invocation: true hace que la skill solo corra cuando tú escribes /revisar-rama: Claude nunca la lanza por su cuenta. Úsalo en las skills que tienen efectos (commits, deploys, migraciones) o que cuestan mucho, como esta, que lanza tres subagentes.

Qué cambia con context: fork

Es una sola línea en el frontmatter de la skill, pero cambia dónde y cómo se ejecuta:

Skill normalSkill con context: fork
Dónde correEn tu conversación, con el mismo ClaudeEn un subagente nuevo, del tipo que diga agent: (por defecto general-purpose)
Qué sabeTodo lo que ya hablaron en la sesiónSolo el texto de la skill y los argumentos. No ve tu conversación
Qué ves mientras trabajaCada paso, en tu sesiónNada: corre en segundo plano y sigues trabajando. Con background: false, esperas el resultado
Qué queda en tu contextoTodo lo que leyó y ejecutóSolo el resumen que devuelve
ModeloEl de la sesión, o model: mientras respondemodel: fija el modelo del subagente
Ojo con el nombre. "Fork" suena a copiar la conversación, pero no la copia: el subagente arranca sin saber nada de lo que hablaste. Por eso la skill tiene que traer todo lo que necesita, y lo que cambia entre usos va en los argumentos ($ARGUMENTS). Si usas agent: Explore, ni siquiera carga el CLAUDE.md.
  • Úsalo cuando…La skill lee mucho para devolver poco: investigar un flujo, auditar dependencias, resumir logs, revisar un módulo.
  • No lo uses cuando…La skill depende de lo que ya hablaron, tiene que editar archivos mientras tú miras, o te va a hacer preguntas a mitad de camino.
