¿Qué pieza necesito? Preguntas rápidas

  • "Claude siempre debería saber esto sobre el repo"CLAUDE.md (o una regla con paths si aplica solo a ciertos archivos)
  • "Esto se hace en 6 pasos y siempre igual"Skill
  • "Esto tiene que pasar siempre, sin depender de que Claude se acuerde"Hook (por ejemplo, formatear después de cada edición)
  • "Esto no debe pasar nunca"Regla deny (por ejemplo, leer el .env o publicar el paquete)
  • "Necesito que alguien revise/investigue sin ensuciar mi sesión"Subagente
  • "Claude necesita ver datos de Jira, GitHub, la BD o docs internas"MCP / conector
  • "Quiero que 12 repos tengan lo mismo"Plugin en un marketplace del equipo

Hook o deny: lo que no depende de que Claude se acuerde

Las dos cosas las aplica Claude Code, no el modelo, así que funcionan aunque Claude olvide una instrucción. Pero resuelven problemas opuestos: el hook hace que algo pase en un momento fijo; el deny impide una acción.

.claude/settings.json · un hook y una regla deny
{
  "permissions": {
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Bash(npm publish *)"
    ]
  },
  "hooks": {
    "PostToolUse": [
      { "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/formatear.sh" }] }
    ]
  }
}

Con esto, Claude no puede leer los .env ni publicar el paquete aunque se lo pidan, y cada archivo que edita se formatea solo. Las reglas deny se ven a fondo en la sesión 4, y los hooks, con eventos y más ejemplos, en la sesión 5.

Tokens: la unidad con la que se mide todo

Claude no lee palabras ni caracteres: lee tokens, fragmentos de texto que pueden ser una palabra corta, un pedazo de una palabra larga, un signo o un espacio. Todo lo que entra al modelo y todo lo que sale se cuenta en tokens, y con esa unidad se miden tres cosas: cuánto cabe en el contexto, cuánto cuesta una tarea y cuánta cuota del plan consumes.

Ejemplo ilustrativo · el mismo texto en tokens
# Español: 6 palabras ≈ 10 tokens
Claude refactorizó el servicio de reembolsos
[Claude][ ref][actor][izó][ el][ servicio][ de][ re][emb][olsos]

# Inglés: 5 palabras ≈ 6 tokens
Claude refactored the refunds service
[Claude][ refactor][ed][ the][ refunds][ service]

La división es ilustrativa: Anthropic no publica cómo corta su tokenizador. Lo que sí se mantiene: las palabras comunes en inglés suelen ser un solo token, las largas o en otros idiomas se parten en pedazos, y el espacio va pegado a la palabra siguiente. Para un conteo exacto, usa count_tokens.

Lo que más sorprende al principio: el modelo no recuerda entre mensajes. Cada vez que escribes, Claude Code le vuelve a enviar todo el contexto acumulado: instrucciones, CLAUDE.md, archivos leídos e historial. Por eso una sesión larga con temas mezclados se vuelve más lenta y más cara en cada turno. La caché abarata lo que se repite, pero igual ocupa espacio y se paga.

Qué se carga en cada turno, cómo medirlo y cómo ahorrar tokens sin perder calidad está en su propio capítulo: Consumo y eficiencia.

Modelos disponibles y su consumo

Cuánto consume cada modelo por token, tomando Haiku 5.5 como base (octubre de 2026):

ModeloConsumo por tokenEsfuerzo por defectoPara qué
Haiku 5.51×mediumTareas cortas, de mucho volumen y subagentes de búsqueda.
Sonnet 5.520×mediumEl día a día: features, tests, explicar código.
Opus 5.540×mediumTrabajo complejo. Modelo por defecto de Claude Code.
Fable 5.1100×highLo más difícil: arquitectura, bugs complejos.

Ojo con Haiku 5.5 en sesiones largas: si el prompt pasa de 100.000 tokens, cuesta 5 veces más. En Claude Code eso llega rápido, porque cada turno envía todo el contexto; ahí Haiku 5.5 queda en 5× y Sonnet solo 4 veces por encima. En Bedrock y Vertex, el alias haiku todavía apunta a Haiku 4.5, que cuesta 10×.

El esfuerzo multiplica encima de esto: más esfuerzo es más razonamiento, y el razonamiento se cobra como salida, que cuesta 5 veces la entrada. No hay un multiplicador fijo por nivel; mídelo con /usage. Precios en la página oficial.

Modelo y esfuerzo: ejemplos concretos

Dos perillas independientes. El modelo define cuánta capacidad tiene; el esfuerzo define cuánto de esa capacidad usa en cada respuesta. Más de cualquiera de las dos significa respuestas más lentas y más consumo de la cuota del plan.

En Claude Code el modelo por defecto es Opus 5.5 con esfuerzo medium (los valores de cada modelo están en la tabla de arriba). Así se eligen según la tarea:

Cómo cambiarlos en Claude Code

/model abre el selector (← → ajustan el esfuerzo).
/effort xhigh cambia solo el esfuerzo.
claude --model sonnet --effort low al arrancar.
Escribe ultrathink en un prompt para razonar más solo en ese turno.
En subagentes y skills: model: y effort: en el frontmatter.
CLAUDE_CODE_SUBAGENT_MODEL=haiku fija el modelo por defecto de los subagentes.

Errores típicos

Dejar max para todo: gasta cuota y puede "sobrepensar" tareas simples.
Usar Haiku para diseñar: ahorras tokens y pierdes horas corrigiendo.
Cambiar de modelo a mitad de una tarea larga sin necesidad: el nuevo modelo relee todo el contexto.
Culpar al modelo cuando faltó contexto: casi siempre el problema es el prompt o el CLAUDE.md.

¿En qué idioma escribirle a Claude?

Claude entiende y responde muy bien en español. La pregunta real es de costo en tokens y de consistencia.

Lo que dicen las mediciones

  • El tokenizador divide el texto en fragmentos y está optimizado para el inglés. Una medición con el endpoint oficial count_tokens (Sonnet 4.6, junio 2026) dio 1.16 tokens por palabra en inglés y 1.72 en español, alrededor de 48% más para el mismo contenido.
  • Otro análisis de ~2,000 sesiones reales de Claude Code encontró prompts en español entre 44% y 63% más costosos (promedio ~54%)… pero los prompts eran solo ~10% del contexto total. El resto es código, archivos leídos y salidas de herramientas, que no cambian con el idioma. El sobrecosto real quedó cerca de 5%, sin diferencia apreciable de calidad en tareas de código.
  • La proporción cambia entre modelos porque no todos usan el mismo tokenizador. Son mediciones puntuales, no cifras oficiales de Anthropic: repítelas con textos de tu equipo usando count_tokens, o compara /context y /usage en sesiones reales.
