Skill vs. agent: the most confusing difference

Skill = "how it's done"

It's procedural knowledge. While unused, Claude only sees its name and description (a few lines). When invoked, its instructions enter the current conversation's context and the same Claude follows them. You see every step.

Examples: creating an EF Core migration, preparing a release, the changelog format, the checklist for a new endpoint.

Subagent = "who does it"

It's a separate worker. It starts with a clean context (it doesn't see your conversation), uses only the tools you allow and can use another model. It can read 40 files and return a 20-line summary: your main session doesn't fill up.

Examples: security reviewer, code researcher, test writer, log analyst.

Which piece do I need? Quick questions

  • "Claude should always know this about the repo"CLAUDE.md (or a rule with paths if it only applies to certain files)
  • "This takes 6 steps and is always done the same way"Skill
  • "This must happen no matter what, without relying on Claude remembering"Hook or deny rule
  • "I need someone to review/research without cluttering my session"Subagent
  • "Claude needs to see data from Jira, GitHub, the DB or internal docs"MCP / connector
  • "I want 12 repos to have the same setup"Plugin in a team marketplace

Model and effort: concrete examples

Two independent knobs. The model sets how much capability there is; effort sets how much of that capability each response uses. More of either means slower answers and more of the plan's quota.

In Claude Code the default effort is high. Levels: low, medium, high, xhigh, max. The default model depends on the seat: Sonnet 5 on Team Standard and Opus 5 on Team Premium and Enterprise.

How to change them in Claude Code

/model opens the picker (← → adjust effort).
/effort xhigh changes only the effort.
claude --model sonnet --effort low at startup.
Type ultrathink in a prompt to reason more for that turn only.
In subagents and skills: model: and effort: in the frontmatter.
CLAUDE_CODE_SUBAGENT_MODEL=haiku sets the default subagent model.

Common mistakes

Leaving max on for everything: burns quota and can "overthink" simple tasks.
Using Haiku for design: you save tokens and lose hours fixing things.
Switching models mid-way through a long task for no reason: the new model rereads the whole context.
Blaming the model when context was missing: the problem is almost always the prompt or CLAUDE.md.

Which language should you write to Claude in?

Claude understands and answers very well in Spanish and many other languages. For non-English-speaking teams, the real question is about token cost and consistency.

What the measurements say

  • The tokenizer splits text into chunks and is optimized for English. A measurement with the official count_tokens endpoint (Sonnet 4.6, June 2026) gave 1.16 tokens per word in English and 1.72 in Spanish, about 48% more for the same content.
  • Another analysis of ~2,000 real Claude Code sessions found Spanish prompts 44% to 63% more expensive (average ~54%)… but prompts were only ~10% of the total context. The rest is code, files read and tool output, which don't change with the language. The real overhead ended up around 5%, with no noticeable quality difference on coding tasks.
  • The ratio varies between models because they don't all use the same tokenizer. Measure your own case with /context or /usage.
