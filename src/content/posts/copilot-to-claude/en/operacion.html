The commands that separate someone who "uses Claude" from someone who handles it fluently: naming and resuming sessions, working in parallel, turning plugins on and off, controlling costs and keeping everything up to date.

A recommended work routine

A normal day with Claude Code
# 1. Start with a name: you'll find it easily later
claude -n "PAY-482-partial-refund"

# 2. Inside the session
/model            # model and effort suited to the task
/plan …           # plan before touching code
/context          # check how much context you're using
/diff             # review changes
/code-review      # a second look
/usage            # what it cost

# 3. The next day, pick up where you left off
claude -r "PAY-482-partial-refund"

Sessions: name, resume, branch

Working in parallel

  • claude --bg "investigate the flaky payments test"Launches a background session and gives you your terminal back.
  • /background [prompt]Sends the current session to the background.
  • /fork [prompt]Copies the conversation into a new background session.
  • /tasks · /list-agentsSee background work, subagents and other sessions.
  • isolation: worktree (subagents)The subagent works in an isolated git worktree so it doesn't step on your files.
  • /desktop · /mobileContinue the session in the desktop app · QR code for the mobile app.
  • claude.ai/codeCloud sessions on GitHub; several at once from the browser or your phone.
Parallel without conflicts: two sessions editing the same folder step on each other. For real parallel work use git worktrees (one folder per branch) or cloud sessions.

Plugins: install, enable, disable

Inside Claude Code
/plugin                                         # panel: Discover · Installed · Marketplaces · Errors · Stats
/plugin install csharp-lsp@claude-plugins-official
/plugin list --enabled                          # or --disabled
/plugin disable csharp-lsp@claude-plugins-official
/plugin enable  csharp-lsp@claude-plugins-official
/plugin uninstall csharp-lsp@claude-plugins-official
/reload-plugins                                 # applies changes made outside the panel

/plugin marketplace add my-org/claude-plugins
/plugin marketplace update company-tools
/plugin marketplace list
From the shell (scripts, onboarding)
claude plugin install platform-tools@company-tools --scope project
claude plugin uninstall platform-tools@company-tools --scope project
claude plugin details platform-tools@company-tools   # which skills, agents, hooks and MCP it ships
  • Scopes: user (you, all repos), project (the whole team, written to .claude/settings.json), local (you, this repo only). Managed-scope plugins are set by the admin and can't be removed.
  • If you uninstall a plugin the project enables, Claude Code asks whether to disable it just for you (override in settings.local.json) or for everyone.
  • The Installed tab flags plugins as "Not used recently": disable them, because each one consumes context on every turn.
  • The panel shows a plugin's context cost before you install it.
  • Useful plugins from the official marketplace: csharp-lsp and typescript-lsp (Claude sees compile errors while editing; they require installing csharp-ls or typescript-language-server), github, atlassian, commit-commands, pr-review-toolkit, security-guidance.

Skills, subagents, MCP and hooks

  • Skills/skills list and hide · /skill-doctor context cost and usage · disable the ones you don't use to save context
  • Subagents/agents create and edit · /list-agents see active ones · claude --agent name the whole session as that agent
  • MCP/mcp status and OAuth · /mcp disable name / enable / reconnect · claude mcp list, get, remove
  • Hooks/hooks see configured ones · "disableAllHooks": true temporarily disable all · claude --debug see runs
  • Permissions/permissions · /fewer-permission-prompts suggests an allowlist based on your sessions
  • Memory/memory edits CLAUDE.md and auto memory

Customizing the environment

  • /configAll settings in one panel, or /config key=value.
  • /statusline show model, branch and context %Claude generates a status line to your liking.
  • /output-styleChanges the answer style (e.g. explanatory, for learning).
  • /theme · /keybindings · /colorTheme, shortcuts and bar color (handy for telling sessions apart).
  • /add-dir ../other-repo · /cd pathGive access to another folder · move the session.
  • /ideConnect to VS Code or JetBrains from an external terminal.
~/.claude/settings.json · minimal status line
{
  "statusLine": {
    "type": "command",
    "command": "jq -r '\"[\\(.model.display_name)] \\(.context_window.used_percentage // 0)% context\"'"
  }
}

Health, costs and updates

  • /usage (alias /cost)The session's tokens and cost.
  • /contextWhat's taking up context: CLAUDE.md, MCP, skills, history.
  • /statusModel, account, version, permission mode.
  • /doctorDiagnoses and fixes installation and configuration problems.
  • /insightsHTML report analyzing your recent sessions.
  • claude update · /upgrade · claude --versionUpdate and check the version.

In claude.ai

  • Customize → Skills: turn skills on or off (organization skills come on; you can turn them off for yourself).
  • Customize → Connectors: connect accounts. In each chat, the tools menu lets you turn off connectors you don't need to save context.
  • Settings: pause or reset memory, incognito chats, default model and effort.
  • Projects: rename, archive and change sharing permissions.
  • Skills and plugins enabled in claude.ai sync to Claude Code. Synced plugins show up in /plugin → Installed with origin synced; you disable them there, unless the organization marks them as required.
