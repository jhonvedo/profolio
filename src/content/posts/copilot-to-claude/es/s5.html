Al terminar, cada persona puede

  • Escribir hooks que formatean, protegen archivos y verifican antes de terminar.
  • Empaquetar un procedimiento del equipo como skill.
  • Crear un subagente especializado con herramientas limitadas.

Curso complementario: Introduction to Agent Skills · Introduction to Subagents

HerramientaQué esGarantía
CLAUDE.md / rulesContexto e instruccionesClaude intenta seguirlas
HooksComandos que Claude Code ejecuta en eventos del ciclo de vidaSiempre se ejecutan

Regla práctica: si algo debe pasar siempre (formatear, bloquear secretos, correr tests), es un hook. Si es "cómo hacemos X", es una skill o una regla.

Anatomía

Forma de la configuración
{
  "hooks": {
    "NombreDelEvento": [
      {
        "matcher": "Edit|Write",         // qué herramienta; vacío = todas
        "hooks": [
          {
            "type": "command",           // también: http, mcp_tool, prompt, agent
            "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/x.sh",
            "if": "Edit(*.cs)",           // filtro opcional con sintaxis de permisos
            "timeout": 60                  // segundos
          }
        ]
      }
    ]
  }
}

Los comentarios // son solo explicativos: JSON no admite comentarios en el archivo real.

Entrada

JSON por stdin: session_id, cwd, hook_event_name, tool_name, tool_input (p. ej. tool_input.file_path, tool_input.command).

Exit 0

Todo bien. En SessionStart y UserPromptSubmit el stdout se agrega como contexto para Claude.

Exit 2

Bloquea. El stderr se usa como motivo y Claude lo lee. Otros códigos son errores no bloqueantes.

Para control fino, imprime JSON en stdout. Los valores de permissionDecision son allow, deny o ask. Los campos específicos del evento van dentro de hookSpecificOutput; si los pones arriba, se ignoran sin error.

Salida JSON de un hook
// PreToolUse: decidir por la herramienta
{ "hookSpecificOutput": { "hookEventName": "PreToolUse",
    "permissionDecision": "deny", "permissionDecisionReason": "…" } }

// Stop: no dejar terminar
{ "decision": "block", "reason": "…" }

Hook 1 · Proteger archivos sensibles (PreToolUse)

.claude/hooks/proteger-archivos.sh
#!/usr/bin/env bash
# Bloquea ediciones a archivos que solo deben cambiar humanos.
INPUT=$(cat)
FILE=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')
FILE="${FILE//\\//}"   # normaliza rutas de Windows

PROTEGIDOS=(".env" ".git/" "appsettings.Production.json" "/Migrations/""pnpm-lock.yaml" "prisma/migrations/")

for p in "${PROTEGIDOS[@]}"; do
  if [[ "$FILE" == *"$p"* ]]; then
    echo "Bloqueado: $FILE es un archivo protegido ($p). Las migraciones se generan con dotnet ef.Usa los comandos de pnpm/prisma." >&2
    exit 2
  fi
done
exit 0

Hook 2 · Formatear después de editar (PostToolUse)

.claude/hooks/formatear.sh · .NET
#!/usr/bin/env bash
FILE=$(jq -r '.tool_input.file_path // empty')
case "$FILE" in
  *.cs)
    dotnet format "$CLAUDE_PROJECT_DIR/Orders.sln" --include "$FILE" --no-restore >/dev/null 2>&1 ;;
esac
exit 0
.claude/hooks/formatear.sh · Node
#!/usr/bin/env bash
FILE=$(jq -r '.tool_input.file_path // empty')
case "$FILE" in
  *.ts|*.tsx|*.js|*.json|*.md)
    cd "$CLAUDE_PROJECT_DIR" && pnpm exec prettier --write "$FILE" >/dev/null 2>&1
    pnpm exec eslint --fix "$FILE" >/dev/null 2>&1 ;;
esac
exit 0

Hook 3 · No terminar con tests en rojo (Stop)

.claude/hooks/tests-verdes.sh
#!/usr/bin/env bash
INPUT=$(cat)
# Evita bucles: si ya obligamos a continuar una vez, deja terminar.
if [ "$(echo "$INPUT" | jq -r '.stop_hook_active')" = "true" ]; then exit 0; fi

cd "$CLAUDE_PROJECT_DIR"
# Solo verifica si hay cambios sin commit.
git diff --quiet && git diff --cached --quiet && exit 0

if ! OUT=$(dotnet test --nologo -v qpnpm -r test 2>&1); then
  echo "Los tests fallan. Corrígelos antes de terminar:" >&2
  echo "$OUT" | tail -n 40 >&2
  exit 2
fi
exit 0

Hook 4 · Contexto al iniciar (SessionStart)

.claude/hooks/contexto.sh
#!/usr/bin/env bash
cd "$CLAUDE_PROJECT_DIR"
echo "Rama actual: $(git branch --show-current)"
echo "Últimos commits:"; git log --oneline -5
exit 0

Registrarlos en .claude/settings.json

.claude/settings.json (sección hooks)
{
  "hooks": {
    "SessionStart": [
      { "matcher": "startup|resume",
        "hooks": [{ "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/contexto.sh" }] }
    ],
    "PreToolUse": [
      { "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/proteger-archivos.sh" }] }
    ],
    "PostToolUse": [
      { "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/formatear.sh" }] }
    ],
    "Stop": [
      { "hooks": [{ "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/tests-verdes.sh", "timeout": 300 }] }
    ],
    "Notification": [
      { "matcher": "permission_prompt|idle_prompt",
        "hooks": [{ "type": "command", "command": "notify-send 'Claude Code' 'Necesita tu atención'" }] }
    ]
  }
}
  • Haz los scripts ejecutables: chmod +x .claude/hooks/*.sh.
  • La notificación usa notify-send (Linux). En macOS usa osascript -e 'display notification "…" with title "Claude Code"'; en Windows, un script de PowerShell. Como depende del SO, ponla en ~/.claude/settings.json, no en el repo.
  • /hooks muestra los hooks cargados. claude --debug registra cada ejecución.
  • Un hook que sale con código 2 bloquea incluso si hay una regla allow; pero un hook que dice "allow" no anula un deny.
Seguridad: los hooks ejecutan comandos con tus permisos. Revisa los hooks de un repo antes de confiar en la carpeta, igual que revisarías un script de postinstall.

Skills

Una skill es una carpeta con SKILL.md (frontmatter + instrucciones) y, opcionalmente, scripts y archivos de referencia. Claude solo tiene en contexto la descripción de cada skill; el contenido completo se carga al usarla (divulgación progresiva). Se invocan con /nombre o Claude las usa solo cuando la descripción encaja.

Los antiguos comandos en .claude/commands/*.md siguen funcionando y ahora son equivalentes a skills; para trabajo nuevo usa .claude/skills/.

.claude/skills/nueva-migracion/SKILL.md
---
description: Crea y valida una migración de EF Core. Úsala cuando el usuario cambie entidades o pida una migración.
argument-hint: "[NombreDeLaMigracion]"
disable-model-invocation: true
allowed-tools: Bash(dotnet ef *) Bash(dotnet build *) Read Grep
---
## Estado actual
!`git status --short`

## Tarea
1. Verifica que el build pasa: `dotnet build Orders.sln`.
2. Crea la migración: `dotnet ef migrations add $ARGUMENTS -p src/Orders.Infrastructure -s src/Orders.Api`.
3. Lee el archivo generado y reporta: tablas/columnas afectadas, pérdida de datos posible, índices.
4. Si hay `DropColumn` o cambios de tipo, detente y pide confirmación.
5. Genera el script idempotente para revisión: `dotnet ef migrations script --idempotent`.
.claude/skills/nuevo-endpoint/SKILL.md
---
description: Crea un endpoint NestJS completo (DTO zod, servicio, controller, tests). Úsala cuando pidan un endpoint nuevo en apps/api.
argument-hint: "[recurso] [verbo]"
arguments: [recurso, verbo]
allowed-tools: Bash(pnpm --filter api *) Read Grep Glob Edit Write
---
## Referencia
Sigue el patrón de [ejemplo-endpoint.md](ejemplo-endpoint.md).

## Tarea
Crea el endpoint `$verbo` para el recurso `$recurso`:
1. DTO con zod en `apps/api/src/$recurso/dto/`.
2. Método en el servicio con manejo de errores tipado.
3. Ruta en el controller con guard de autenticación.
4. Tests unitarios del servicio y un test e2e con Supertest.
5. Corre `pnpm --filter api test` y `pnpm --filter api typecheck`.
  • descriptionQué hace y cuándo usarla. Claude decide con esto; escribe primero el caso principal.
  • disable-model-invocation: trueSolo tú la invocas (deploys, migraciones, cualquier cosa con efectos).
  • user-invocable: falseSolo Claude la usa (conocimiento de referencia).
  • allowed-toolsHerramientas pre-aprobadas mientras corre.
  • argument-hint, argumentsArgumentos: $ARGUMENTS, $0, $1 o $nombre.
  • context: fork + agentEjecuta en un subagente aislado.
  • paths, model, effortActivar por ruta; forzar modelo o esfuerzo.

!`comando` ejecuta el comando antes de enviar la skill y reemplaza el marcador con la salida, así Claude recibe datos reales. Mantén SKILL.md por debajo de 500 líneas y mueve el detalle a archivos de apoyo. /skills lista las skills y /skill-doctor revisa cuánto contexto consumen.

Skills en claude.ai y en Claude Code: el mismo formato sirve en ambos. Las skills que un admin provisiona en la organización se sincronizan a Claude Code y aparecen como /anthropic-skills:<nombre>.

Subagentes

Un subagente trabaja en su propio contexto y devuelve solo el resultado, así la sesión principal no se llena con archivos leídos. Claude Code trae Explore (búsqueda de solo lectura), Plan y general-purpose. Los propios se crean con /agents o a mano:

.claude/agents/revisor-seguridad.md
---
name: revisor-seguridad
description: Revisa cambios buscando vulnerabilidades (inyección, authz, secretos, deserialización). Úsalo antes de abrir un PR que toque autenticación, pagos o datos personales.
tools: Read, Grep, Glob, Bash
model: opus
---
Eres un revisor de seguridad para APIs ASP.NET CoreAPIs NestJS y apps Next.js.
1. Lee `git diff main...HEAD`.
2. Revisa: validación de entrada, autorización por recurso, consultas parametrizadas,
   secretos en código o logs, CORS, manejo de errores que filtre información.
3. Reporta solo hallazgos con evidencia: archivo, línea, riesgo, escenario de explotación y corrección.
4. No edites archivos ni ejecutes comandos que modifiquen el repositorio.
  • Invócalo en lenguaje natural ("usa el revisor-seguridad") o con @"revisor-seguridad (agent)".
  • Campos útiles: tools/disallowedTools, model (sonnet, opus, haiku, fable, inherit), permissionMode, skills, mcpServers, memory, isolation: worktree, maxTurns.
  • Prioridad por nombre: managed → --agents → .claude/agents/ → ~/.claude/agents/ → plugins.

Práctica

Laboratorio 5 · Automatizar el repo

75 min
  1. Crea .claude/hooks/ con los cuatro scripts y regístralos. Verifica con /hooks.
  2. Pide a Claude que edite .env: el hook debe bloquearlo y Claude debe explicar por qué.
  3. Rompe un test a propósito y pide un cambio menor: el hook de Stop debe obligar a Claude a arreglarlo.
  4. Convierte un procedimiento del equipo en skill (migración, release, nuevo endpoint). Pruébalo con /nombre.
  5. Crea el subagente de seguridad y úsalo sobre la rama del laboratorio 3.
  6. Abre un PR con todo y pide revisión a otra persona.
