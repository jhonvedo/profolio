Modelos y esfuerzo

  • Claude Fable 5.1El más capaz para código y trabajo de conocimiento (septiembre 2026). Refactors grandes, diseño de arquitectura, bugs difíciles.
  • Claude Opus 5Tareas complejas de varios pasos con buen balance de velocidad. Tiene modo Fast.
  • Claude Sonnet 5Trabajo diario: features medianas, tests, explicación de código. Rápido y económico.
  • Claude Haiku 4.5Tareas cortas y de alto volumen; buen candidato para subagentes de búsqueda.

Ejemplos concretos por tipo de tarea en Conceptos → Modelo y esfuerzo. El esfuerzo (Low, Medium, High, Extra High, Max) controla cuánto razona el modelo antes de responder. Más esfuerzo es mejor para problemas ambiguos y peor para preguntas simples, porque tarda más y consume más cuota. En Fable 5.1 y Opus 5 el razonamiento ("Thinking") siempre está activo.

Projects: el conocimiento compartido del equipo

Un Project agrupa chats con tres cosas en común: archivos de conocimiento, instrucciones y su propia memoria. Es el lugar para lo que no vive en el repositorio: ADRs, estándares de API, guías de estilo, documentación de negocio, contratos OpenAPI.

  • Capacidad: cuando el conocimiento se acerca al límite de contexto, Claude activa RAG automáticamente y busca en los archivos en vez de cargarlos todos (hasta ~10× más capacidad). Límite de 30 MB por archivo.
  • Compartir (Team/Enterprise): "Can view" o "Can edit", con personas, listas o toda la organización. Aparecen en "Shared with me".
  • Instrucciones: escríbelas como a un compañero nuevo: stack, convenciones, qué evitar, formato de respuesta.

Memoria y chats pasados

La memoria guarda hechos durables (rol, preferencias, decisiones) como temas editables. Cada Project tiene su propia memoria separada. La búsqueda en chats pasados permite preguntar "¿qué decidimos sobre el versionado de la API?". Se puede pausar, reiniciar o usar chats incógnito.

Regla del equipo. La memoria personal no sustituye la documentación. Si una decisión afecta a todos, va a un ADR en el repo o al conocimiento del Project, no a la memoria de una persona.

Artifacts, Docs y Slides

Artifacts

Páginas, diagramas, SVG y apps React que Claude publica con su propio enlace. Pueden llamar a Claude y a conectores (cada visitante usa su propia cuota).

Claude Docs

Documentos vivos con coedición, comentarios y @Claude en el hilo. Exporta a .docx, PDF, .md o Google Docs. Ideal para specs y postmortems.

Claude Slides

Presentaciones 16:9 exportables a PPTX o PDF. Para demos de sprint y propuestas técnicas.

Research, archivos y conectores

  • Research ("+" → Research): varias búsquedas encadenadas con citas. Útil para comparar librerías o evaluar una migración. Requiere búsqueda web activa.
  • Creación de archivos: Claude genera y edita .xlsx, .pptx, .docx y PDF ejecutando código en un entorno aislado. El admin controla la salida a internet de ese entorno.
  • Conectores: GitHub, Jira/Confluence, Linear, Slack, Google Drive, Notion, Figma. Heredan los permisos del usuario en el sistema de origen: Claude no ve nada que tú no puedas ver.
  • Skills de organización: un admin sube un .zip con SKILL.md en Organization settings → Skills y queda disponible para todos (sesión S5).

Datos y privacidad en planes comerciales

Lo esencial: las conversaciones de Team y Enterprise no se usan para entrenar modelos por defecto. La excepción es el feedback con pulgar arriba/abajo, que conserva esa conversación; el admin puede desactivarlo con el ajuste "Rate chats". Enterprise añade retención personalizada, audit logs, SCIM y claves administradas por el cliente.

Práctica

Laboratorio 1 · Project del equipo

45 min
  1. Crea un Project con el nombre del producto. Sube 3–5 documentos reales: un ADR, el estándar de API, el contrato OpenAPI de un servicio y la guía de estilo.
  2. Escribe instrucciones a partir de la plantilla de arriba y ajústalas a tu equipo.
  3. Pregunta: "Según nuestros ADRs, ¿cómo deberíamos exponer un endpoint de reembolsos?". Revisa si cita los documentos correctos.
  4. Cambia a Sonnet 5 con esfuerzo bajo y repite. Compara calidad y tiempo con Fable 5.1 en esfuerzo alto.
  5. Pide un Claude Doc con el diseño del endpoint y deja un comentario con @Claude pidiendo añadir los casos de error.
  6. Comparte el Project con el equipo como "Can view".
