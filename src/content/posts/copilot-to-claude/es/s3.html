Instalación

macOS · Linux · WSL
curl -fsSL https://claude.ai/install.sh | bash
Windows · PowerShell
irm https://claude.ai/install.ps1 | iex
# alternativa
winget install Anthropic.ClaudeCode

El instalador nativo se actualiza solo. También existen Homebrew (brew install --cask claude-code) y npm (npm install -g @anthropic-ai/claude-code, requiere Node 22+).

Luego, en la carpeta del repo: claude → inicia sesión con la cuenta de claude.ai de la organización. Para el IDE instala la extensión de VS Code (también funciona en Cursor) o el plugin de JetBrains (Rider para .NET, WebStorm para Node). Ambos muestran los diffs en el visor del IDE y comparten la selección actual con Claude.

Windows y .NET: Claude Code funciona nativo en Windows. Si tu tooling vive en WSL, instala dentro de WSL y abre el repo desde ahí. Para que los hooks de ejemplo de este curso funcionen en Windows nativo necesitas Git Bash (que Claude Code usa para los hooks) y jq.

El ciclo de trabajo

1 · Explorar

"Lee el módulo de pagos y explícame cómo se procesa un reembolso. No cambies nada todavía." Claude busca, lee y resume.

2 · Planear

Shift+Tab hasta Plan (o /plan). Claude investiga en solo lectura y presenta un plan. Corrígelo antes de aprobarlo.

3 · Implementar

Aprueba el plan. Claude edita, ejecuta el build y los tests, y corrige hasta que pasan.

4 · Verificar y cerrar

/diff para revisar, /code-review para una segunda mirada, y pide el commit con un mensaje convencional.

Cómo pedir bien

Vago

"Arregla el bug de los reembolsos."

Específico

"El reembolso parcial falla cuando el pedido tiene descuento (issue #482). Reproduce el error con un test que falle en RefundServiceTestsrefund.service.spec.ts, arréglalo sin cambiar la API pública y corre toda la suite."

  • Da el criterio de éxito: un test, un comando que debe pasar, una salida esperada.
  • Referencia archivos con @: @src/Payments/RefundService.cs (con autocompletado).
  • Pega imágenes con Ctrl+V: pantallazos de errores, diseños, diagramas.
  • Corrige temprano: Esc interrumpe; escribe mientras Claude trabaja y el mensaje se encola.

Modos de permisos

Antes de editar un archivo o ejecutar un comando, Claude Code puede pedirte permiso. El modo decide cuánto pregunta. No es una configuración que pones una vez y olvidas: lo normal es cambiar de modo varias veces en la misma tarea, según la fase en la que estés.

Cómo cambiar de modo

Tres formas de elegir el modo
# 1. Durante la sesión: Shift+Tab rota entre los modos.
#    El modo activo aparece debajo del prompt.

# 2. Al arrancar, desde la terminal
claude --permission-mode plan

# 3. Por defecto para el repo, en .claude/settings.json
{ "permissions": { "defaultMode": "plan" } }

También puedes escribir /plan seguido de la tarea para entrar directo a modo Plan con esa petición.

default: pregunta la primera vez

Claude te pide permiso la primera vez que quiere usar cada herramienta o comando. Cuando pregunta, tienes tres opciones: aprobar solo esta vez, aprobar y no volver a preguntar por ese comando en este proyecto, o rechazar y decirle qué hacer distinto.

Ejemplo. Le pides "corre los tests del módulo de pagos". Claude propone dotnet test tests/Payments.Testspnpm --filter api test payments y espera. Si eliges "no volver a preguntar", queda guardado como regla allow y la próxima vez corre sin interrumpirte.

Úsalo en un repo que no conoces o mientras aprendes. En pocos días habrás aprobado los comandos habituales y casi no te preguntará.

plan: pensar antes de tocar

Claude puede leer, buscar y analizar, pero no edita archivos ni ejecuta comandos que cambien algo. Al final presenta un plan y te pregunta cómo seguir.

Ejemplo · modo Plan
# Shift+Tab hasta ver "plan mode on"
> Los reembolsos parciales fallan cuando el pedido tiene descuento (#482).
  Encuentra la causa y propón cómo arreglarlo.

# Claude lee RefundService, los tests y el cálculo de descuentos.
# Luego muestra un plan numerado:
#   1. El descuento se resta dos veces en CalculateRefund…
#   2. Agregar un test que reproduzca #482…
#   3. Corregir el cálculo y correr la suite…

# Y pregunta cómo continuar:
#   · Sí, y aceptar ediciones automáticamente
#   · Sí, y aprobar cada edición
#   · No, seguir planeando

Si algo del plan no te convence, elige seguir planeando y corrígelo: "no cambies la firma de CalculateRefund, otros servicios la usan". Corregir un plan cuesta segundos; deshacer código cuesta mucho más.

Úsalo en cualquier cambio de más de un archivo, en código que no conoces y siempre que la tarea sea ambigua.

acceptEdits: implementar sin interrupciones

Claude edita archivos y usa comandos básicos de archivos (crear carpetas, mover) sin preguntar. Los demás comandos, como tests, git o instalar paquetes, siguen las reglas de permisos: si no están aprobados, pregunta.

Ejemplo. Aprobaste el plan de #482 eligiendo "aceptar ediciones automáticamente". Claude escribe el test, corrige el cálculo y actualiza dos archivos más sin detenerse. Tú ves cada diff pasar en la terminal o en el IDE. Si ves algo que no te gusta, presionas Esc, le dices qué cambiar y sigue.

Úsalo después de aprobar un plan. Cuidado: que no pregunte no significa que no debas mirar. Revisa con /diff al terminar.

auto: tareas largas con supervisión ligera

Claude decide solo qué aprobar, con un clasificador de seguridad que revisa cada acción en segundo plano y frena las riesgosas.

Ejemplo. "Migra los 40 endpoints de controllers a Minimal APIs siguiendo el patrón de OrdersEndpoints". Es largo y repetitivo; no quieres aprobar 200 acciones. En auto avanza mientras tú haces otra cosa, y revisas el resultado al final.

Úsalo para trabajo largo y bien definido, idealmente en una rama aparte. Si no aparece al rotar con Shift+Tab, consulta con el administrador del plan.

dontAsk: sin nadie mirando

Todo lo que requeriría preguntar se rechaza automáticamente. Solo corre lo que ya está aprobado en las reglas o en la línea de comandos. Es el modo para scripts y pipelines, donde no hay nadie para responder.

Ejemplo · revisión en un pipeline
claude -p "Revisa el diff contra main y lista riesgos" \
  --permission-mode dontAsk \
  --allowedTools "Read,Grep,Bash(git diff *)"

Aquí Claude puede leer, buscar y ver el diff. Si intenta cualquier otra cosa, se le niega y sigue con lo que tiene.

bypassPermissions: nunca pregunta

Claude hace todo sin pedir permiso. Equivale a arrancar con claude --dangerously-skip-permissions.

Úsalo solo dentro de un contenedor o una VM desechable, sin credenciales reales ni acceso a producción, por ejemplo un devcontainer para un experimento.

No lo uses en tu máquina de trabajo. Un comando equivocado puede borrar archivos o publicar algo. Los administradores suelen bloquearlo en managed settings (sesión 6).

¿Qué modo uso?

  • Llego a un repo que no conozcodefault o plan
  • Cambio de más de un archivo o tarea ambiguaplan, y al aprobar, acceptEdits
  • Bug con reproducción clara y un solo archivodefault o directo acceptEdits
  • Refactor largo y repetitivo en una ramaauto
  • Script o pipeline de CIdontAsk con --allowedTools
  • Contenedor desechable para experimentarbypassPermissions

Los comandos con /

Escribe / al inicio del prompt y aparece un menú con todos los comandos y una descripción corta; sigue escribiendo para filtrar. Muchos aceptan texto después del nombre. Las skills de tu equipo también aparecen en este menú (sesión 5).

No hace falta aprenderlos todos. Estos son los que se usan en una tarea normal, agrupados por el momento en que los necesitas.

Antes de empezar

  • /initAnaliza el repo y genera un CLAUDE.md inicial. Se usa una vez por repo (sesión 4).
  • /modelAbre el selector de modelo; con ← → ajustas el esfuerzo. Directo: /model sonnet.
  • /effortCambia solo el esfuerzo: /effort low para algo mecánico, /effort xhigh para un bug difícil.
  • /planEntra a modo Plan con la tarea: /plan agrega paginación al endpoint de reembolsos.
  • /add-dirDa acceso a otra carpeta: /add-dir ../shared-contracts si la tarea toca otro repo.

Mientras trabajas: cuidar el contexto

El contexto es todo lo que Claude tiene en la cabeza: tu conversación, los archivos que leyó, las salidas de comandos. Cuando se llena o se mezcla con temas viejos, las respuestas empeoran. Una sesión larga con temas mezclados rinde peor que dos sesiones enfocadas.

  • /contextMuestra qué ocupa el contexto: CLAUDE.md, herramientas MCP, archivos, historial. Mira aquí si Claude empieza a olvidar cosas.
  • /compactResume la conversación para liberar espacio y seguir con la misma tarea. Puedes guiarlo: /compact conserva las decisiones sobre la API y los tests pendientes.
  • /clearBorra la conversación y empieza de cero. Úsalo entre tareas no relacionadas.
  • /btwPregunta lateral que no queda en el historial: /btw ¿qué versión de EF Core usa este repo?
  • /rewindVuelve código y conversación a un punto anterior. Atajo: Esc Esc. Úsalo cuando Claude tomó un mal camino.
  • /branchCrea una rama de la conversación para probar otra idea sin perder la actual.
  • /permissionsVer y editar las reglas allow / ask / deny sin abrir el archivo.

Al terminar

  • /diffMuestra todos los cambios de la sesión. Léelo como si lo hubiera escrito otra persona.
  • /code-reviewSegunda revisión del cambio: bugs, casos límite, código que se puede simplificar.
  • /security-reviewRevisión enfocada en seguridad. Úsalo si tocaste autenticación, pagos o datos personales.
  • /usageTokens y costo de la sesión. Útil para calibrar modelo y esfuerzo.

Sesiones

  • /renamePone nombre a la sesión: /rename PAY-482-reembolso-descuento. Así la encuentras mañana.
  • /resumeAbre la lista de sesiones anteriores para retomar una.
  • /exportGuarda la conversación en un archivo de texto, por ejemplo para documentar una decisión.

Configuración y diagnóstico

  • /configTodos los ajustes en un panel.
  • /memoryEdita CLAUDE.md y la memoria automática (sesión 4).
  • /statusModelo, cuenta, versión y modo de permisos actuales.
  • /doctorDiagnostica problemas de instalación o configuración. Primer paso si algo no funciona.

Sin barra, pero igual de útiles

  • Shift+TabRota entre modos de permisos.
  • EscInterrumpe a Claude sin perder lo que lleva. Luego escribes la corrección.
  • Esc EscAbre el rebobinado (lo mismo que /rewind).
  • @Menciona un archivo con autocompletado: @src/Payments/RefundService.cs.
  • !Ejecuta un comando de shell y Claude ve la salida: !git status.
  • Ctrl+GAbre tu editor para escribir un prompt largo con calma.
  • Ctrl+RBusca en los prompts que escribiste antes.

Práctica

Laboratorio 3 · Primera feature con Claude Code

60 min
  1. En el repo de práctica, abre claude y pide: "Explícame la arquitectura de este repo y cómo corro build y tests."
  2. Activa modo Plan y pide una feature pequeña. Ejemplo: "Agrega GET /orders/{id}/refunds con paginación, validación y tests de integración con WebApplicationFactory." "Agrega GET /orders/:id/refunds en NestJS con paginación, DTO validado con class-validator y tests con Vitest + Supertest."
  3. Corrige al menos un punto del plan antes de aprobarlo.
  4. Cambia a acceptEdits y deja que implemente. Observa cómo corre dotnet testpnpm test y corrige fallos.
  5. Revisa con /diff, corre /code-review y pide el commit.
  6. Revisa /usage para ver cuánto costó la tarea.
